## 1. Review conclusion

The source inventory is complete at 40/40 declarations, but this mapping does not certify any path. For every policy-eligible event, the candidate L05 guard must be acquired **after the approved L00 idempotency arbitration and before the first mutable domain, principal, role, scope, capacity, parent, aggregate, child, lease or notification row lock**. The audience resolver must run in a later SQL command after the lock returns and after one `audience_evaluated_at` is captured.

The source lock paths below are copied from the current command-level manifest and are not endorsed as safe. Every row still needs source-code/function call-graph evidence and a reconciled post-L05 order. Existing conflicts are not repaired by inserting L05 mechanically.

## 2. Global protocol prefix to be reviewed

`L00 → L05 → capture audience_evaluated_at → resolve event-time policy/audience in a fresh SQL command → acquire/revalidate the full candidate and source lock union in the approved total order → source mutation + canonical event + audit + idempotency + outbox + immutable candidate snapshot → commit`.

The actual wrapper must be VOLATILE and use separate internal SQL commands under verified READ COMMITTED. L05 is a candidate, not an admitted rank. The global key pair is TBD. No writer may acquire a conflicting mutable lock before L05.

## 4. Cross-cutting disposition

1. **CMD-001–010:** the candidate-normalized path already places actor/authority/capacity/project locks after L00. L05 would need to precede all of those mutable locks. The precise interaction with conditional L10/T-14 must be proven; do not assume the L05/L10 order is admitted.
2. **CMD-011–013:** session/project parent ordering and closure fences remain unresolved. L05 must precede the first mutable lock, but this does not resolve the underlying parent/child inversion.
3. **CMD-014–022:** assignment, capacity, instrument/version and canonical-identity arbitration require full lock-set reconciliation. The candidate L05 prefix cannot be inserted while preserving a later lower-rank acquisition.
4. **CMD-023–032:** existing unit/association/conflict/claim/inspection order conflicts are blockers independent of L05. Normalize the canonical identity, project/session, assignment, unit, association, claim and inspection order before certifying.
5. **CMD-033–035:** Storage I/O stays outside database transactions. CMD-035 must decide per-operation transaction versus savepoint and correlate each emitted domain event with its durable operation result.
6. **CMD-036–040:** source event may be emitted by an asynchronous finalizer, not the initiating request. The finalizer is the source transaction for event-time audience resolution. Acquire L05 before finalizer lease/source/aggregate locks; preserve the atomic event/audit/outbox/snapshot unit.
7. **CMD-041–044:** report/audit access are not part of these 40 source-domain mutation producers; conditional access events require a separate reviewed boundary.
8. **CMD-049–054:** notification lifecycle commands must not recursively match their own notification events unless an explicit non-recursive policy is approved.
