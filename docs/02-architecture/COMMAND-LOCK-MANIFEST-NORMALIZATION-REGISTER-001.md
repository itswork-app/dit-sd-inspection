## 1. Purpose and certification boundary

This register consolidates the 50 in-scope application command boundaries into one stable field schema. It normalizes source content for review; it does not convert candidate orders into approved PostgreSQL lock plans, prove the effective lock graph acyclic, approve physical schema/constraints/RLS/ACL, or authorize implementation.

The 54-ID traceability inventory remains intact. CMD-045–048 are PO-approved external control-plane responsibilities and are excluded from this application manifest. They intentionally have no application transaction, lock set, route, RPC, worker or permission.

**Coverage accounting:** 50/50 application commands have a candidate execution/transaction boundary recorded in this register. This is not full technical manifest certification. **0/50 are technically approved or certified lock-complete.** The 4 external IDs remain traceability-only.

## 2. Canonical normalized field schema

Every application command is represented against these fields:

1. **Command identity:** stable CMD ID and logical operation.
2. **Boundary kind:** short mutation transaction, bounded read, multi-step durable workflow, or worker/scheduler transaction.
3. **Ordered resources:** candidate lock/arbitration classes and deterministic same-class key order; read commands explicitly state no mutation lock.
4. **Post-lock revalidation:** actor, authority, scope, lifecycle, effective time, version, capacity and source state predicates.
5. **Shared invariant / final arbiter:** unique/exclusion constraint, guarded state transition, parent fence, row version, lease/fencing tuple, or explicit unresolved arbiter.
6. **Competing writers:** all known commands, workers and provider callback paths that can race.
7. **Atomicity / external effects:** domain mutation + audit + idempotency result; durable intent/outbox and external I/O outside DB locks.
8. **Open evidence:** missing physical object, lock mode, implicit FK/index/trigger/function edge, token, RLS/ACL, institutional/provider decision, reviewer approval or test evidence.

A field is not considered closed merely because a candidate value is written. Unknown physical names, lock modes, grants, indexes, functions, or worker identities are recorded as OPEN rather than inferred.

## 3. Shared normalization rules

- L00 idempotency arbitration precedes domain mutation locks; same key with a different semantic request hash rejects, and replay must not repeat side effects.
- L10 capacity serialization applies to every writer that changes the approved T-14 qualifying-Inspector predicate. Acquire all affected project rows in ascending project UUID before L15–L18; re-discover after the fence and abort/retry if the set changed.
- L15 principals, L16 role grants, L17 scope grants and conditional L18 authorization catalog rows use deterministic key order. Actor and target are not actor-first. Exact lock modes and revocation-freshness protocol remain unapproved.
- L20 canonical identity arbitration is used only where canonical serial/instrument identity is actually part of the command; do not add it to unrelated commands.
- L30 project/session parent fences precede dependent child resources; project before session. Candidate modes are not approved until PostgreSQL lock compatibility and implicit edges are reviewed.
- L40 instrument/version, L50 assignment/grouping, L55 assignment membership, L60 unit, L70 association, L80 claim, L90 inspection, L100 dependent aggregates, and L110 append-only facts follow only where applicable.
- Every same-rank multi-row acquisition uses a stable immutable key order. Revalidate all predicates after the governing fence; preflight authorization alone is insufficient.
- Audit and idempotency outcomes commit atomically with the domain mutation. Audit failure aborts the transaction.
- Storage, rendering, malware scan, printer/network and provider I/O never occur while database row locks are held. Use durable intent, lease/fencing and guarded finalization.
- A read boundary does not acquire a fabricated write lock. A missing physical aggregate or uniqueness arbiter remains OPEN.
